The conflict to decide. Your map says all LLM calls go to OpenRouter directly. Of the three, only ADK can keep that rule. Both managed services run their own vendor's models on their own API. Using either one for the bot means relaxing that preference, at least for the jobs you move to it. That decision is yours to make, and it belongs in the map.

How each plugs into the seam

The worker is a Supabase Edge Function with a 150 s wall clock (ticket 01). An agent run can take longer than that. So an agent-ready seam needs two outcomes: done now or pending, collect later.

generate(kind, jobId, bundle) → { done, result } | { pending, runRef }
collect(runRef)               → { done, result } | { pending } | { failed }
// The bot always validates `result` against the fixed shape, then records it.
  • Plain calls (MVP): always return done. Nothing changes for the bot.
  • ADK graph on Cloud Run: load → select (agent node with read tools) → validate → write → validate. The worker POSTs the job and gets pending. Cloud Run posts the result back to a Supabase function, which validates, records and sends it. The session lives only as long as the job.
  • Claude Managed Agents: create a session per job, and put the context bundle in as mounted files so no custom-tool round trips are needed. Give it read-only GitHub access through a vault credential. Collect the result when a webhook says the session went idle.
  • Antigravity: background: true returns an interaction id as the runRef. The existing pg_cron tick polls interactions.get. Credentials go through the network allowlist.

Why mount the bundle instead of exposing tools? Each custom-tool call pauses a managed session until your code answers, so every answer would be another Edge Function invocation. A bundle given up front plus read-only GitHub access avoids those round trips. Keep custom tools for the ADK graph, where tools run in the same process.
