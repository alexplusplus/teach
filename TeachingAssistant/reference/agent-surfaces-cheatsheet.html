Agent surfaces cheat sheet

Which rung each generation belongs on, where state lives, and how the three platforms compare. Facts checked 2026-09-16 (updated the same day for the "agents own memory" assumption).

1 · The ladder and the climbing test

  1. Plain LLM callCode assembles the inputs, and one call returns a fixed shape.
  2. Workflow / ADK 2.0 graphCode fixes the order of steps; nodes are functions, LLM calls or agents.
  3. Agent with toolsThe model decides what to fetch next.
  4. Managed agent sessionA vendor hosts the loop, a sandbox and session state.

Climb only if the model must decide what to fetch mid-task · the job can wait · the gain is worth several times the tokens (~$0.01 plain vs ~$0.03–0.15 agent per Lesson).

2 · Where state lives (depends on your memory decision)

AssumptionRule
Original: generators never write memory; Postgres is the recordSession-per-job. The agent is stateless, reads Postgres through tools or a bundle, and returns fixed shapes.
Current (2026-09-16): agents may write memory; Postgres is only the harnessSession-per-Thread. /next or the morning run creates a session. Taps and Replies are new events. Threads are never closed (2026-09-17), so sessions stay resumable indefinitely, and memories are written incrementally after each turn or when a newer Thread starts.

Harness test: keep it in Postgres if your code needs it deterministically (routing a Telegram update, the Topic's latest Lesson for progression taps, update_id dedup, jobs and runRef, the Topic in progress, the Backlog copy, spend). Session = the open Thread's transcript. Long-term memory = facts that outlast a Thread (what was hard, Notes, recaps).

5 · Seam contract (agent-ready)

generate(kind, jobId, bundle) → { done, result } | { pending, runRef }
collect(runRef)               → { done, result } | { pending } | { failed }

The 150 s Edge wall clock makes pending → collect mandatory for agent engines. Collect through a webhook (Claude Managed Agents, or a Cloud Run callback) or a pg_cron poll (Antigravity). For managed runs, mount the context bundle as files instead of custom tools: each custom-tool call is a round trip through your code.
